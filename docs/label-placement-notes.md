# 标注排版：业界惯例与经典算法（调研 + 我们的取舍）

日期：2026-09-26 ｜ 触发：工艺图上"图元 / 文字 / 线条交叠"这一类问题值不值得继续投
｜ 结论：**两条硬指标我们已经做到 0；剩下的"线穿文字带"不违背制图惯例，不值得为它改引擎**。

> 这份是**领域调研**（凭知识梳理，未逐条联网核对出处）。要对外引用具体标准 / 论文条款，

## 1. 这类问题的正式名字

不叫"避让"，学术界叫 **label placement / map labeling**：

- **点要素**（符号、设备）→ *point-feature label placement (PFLP)*；
- **线要素**（管线、导线、道路）→ *line-feature label placement*。

它被研究四十多年，是 **NP-hard 的组合优化问题**（Marks & Shieber 一脉的复杂度结论）——
所以"写个循环挪一挪"永远只能算启发式，业界的做法是**制图惯例 + 算法支撑**两半一起用。

## 2. 制图惯例（人怎么写图）

| 惯例 | 出处（口径） | 我们的现状 |
|---|---|---|
| 文字方向"从图纸下方或右方读"，旋转文字**自下而上** | ISO 128 / ISO 3098 一脉 | ✅ 竖线长标注用 `-90°`（`style.label.angle`） |
| 管线标注：水平管放**线上方**、竖直管放**线左侧**，并用**文字底框把线断开** | P&ID 通行做法；CAD 里叫 *background mask* / *text gap* | ✅ 底框 + 法向净距；**"贴线"本身合规** |
| 没地方放时：拉**指引线（leader）**把文字移到空白处，或**移到图例 / 表格**（keyed annotation），或降低次要标注密度 | ISO 129 / ASME Y14.5 一脉；P&ID 实践 | ⛔ **没有**（我们目前只做"挪"） |
| 每个域可以有**自己的文字位置约定**（用约定绕开几何冲突） | 本家族先例：电力域包把文字符号**统一放符号右下角**（`ice-entity-designer/docs/power-symbol-spec.md`） | 水务域选的是"位号在上 / 名称在下、居中" |

**最关键的一条**：真正禁止的是"**文字压文字**""**文字压符号**"；
"标签压线（带底框）"是**标准写法**。我们的硬指标正是这两条（都已是 0）。

## 3. 经典算法与工程实现

| 层次 | 做法 | 代表 |
|---|---|---|
| 形式化 | 每个要素给一组**离散候选位**（4 / 8 / 16 个）→ 候选重叠即冲突 → 在**冲突图**上选最大权独立集 | Wagner & Wolff 的组合框架 |
| 求解器 | 贪心 → 局部搜索 → **模拟退火**（当年实证最好）→ 禁忌 / 遗传 / GRASP | Christensen–Marks–Shieber 的实证比较 |
| **线要素专用** | **滑动模型（slider）**：标签沿线滑动，把 2D 冲突降成 1D 区间问题（一维有最优 / 近似结果） | van Kreveld / Strijk / Wolff 一脉 |
| 物理模型 | **力导松弛**：标签当粒子（向锚点弹簧 + 彼此斥力），迭代到稳定 | 地图标注里的 force-based labeling |
| 工程实现 | 候选位 + **加权冲突消解** + 优先级 + 逐要素回退（flip / leader / 丢弃） | ArcGIS **Maplex**、QGIS **PAL**；图绘制里 **ELK** 有 edge-label placement pass、**yFiles** 用 8 候选位 + 全局消解 |
| 交互兜底 | **offset / flip（翻到线另一侧）/ mask** 三个内建动作 + 人工微调 | AutoCAD Plant 3D、SmartPlant P&ID、COMOS |

## 4. 我们做到了哪一步

**已实现**（`src/domain/diagram/label-avoidance.ts` + `DiagramLayer.__avoidLabelOverlaps()`）：

- 离散候位移 + 确定性求解；**默认离线**（法向净距 12，盒边离线 4px）；
- 竖线长标注**转 90°**（合 ISO 自下而上），窄走廊**退回横排**；
- 硬约束"不许压回自己那根线上"；锚点所在折线用"离锚点最近的那段"（不抄引擎的锚点规则）；
- **最受限优先**（fail-first，见下）。

## 5. 离线原型：哪条经典做法真的有用（真实案例，单因子）

数据：真实案例几何 dump（78 单元 / 100 标注，其中 23 条竖排）。
做法：把现行实现**原样复刻**到离线脚本里当基线（复刻的位移中位 / 最大与线上实测**完全一致**，
说明复刻是可信的），然后**一次只加一条**改动比。

| 变体 | 压单元 | 标注互压 | 位移中位 | 位移最大 | 纯沿线 |
|---|---|---|---|---|---|
| 线上现行（实测） | 0 | 0 | 18.0 | **81.2** | — |
| 离线复刻（校验用） | 0 | 0 | 18 | 81.2 | 35 |
| **① + 最受限优先** | 0 | 0 | 18 | **65.5** | 36 |
| ② + 沿线滑动候选 | 0 | 0 | 18 | 81.2 | 36 |
| ①② 两条一起 | 0 | 0 | 21.3 | 65.5 | 37 |

**结论（数据说话）**：

- **只有"最受限优先"有效**：最大位移 81.2 → 65.5（−19%），重叠保持 0/0 —— 采纳。
- **"沿线滑动候选"单独加没有收益**：现有候选集里本来就含沿线方向的位移，Manhattan 走向下
  它没有额外可挖的（这也解释了为什么经典里 slider 主要解决"标签必须贴线"的场景，
  而我们要的是"离线"）。
- 两条一起反而把中位位移从 18 抬到 21.3（多挪了一点点），所以**没有采纳**。

已落地：`planLabelOffsets()` 里按"干净候选位的数量"升序排（同分按输入顺序，保证可复现），
真实案例实测 **位移最大 81.2 → 65.5**，重叠仍是 0/0（单测 + e2e 双双钉住）。

## 6. 还没做的（以及为什么先不做）

1. **放弃 + 图例 / 表格兜底**：密集处不硬放，改到管线表 / 仪表清单，或用编号键化。
   这是制图标准里的标准出路，但**属于产品决策**（图纸要标到什么密度），不是算法问题。
2. **指引线（leader）**：把文字移到远处空白 + 一条线指回锚点。需要引擎支持"标签带引线"，
   而收益集中在极密场景 —— 当前案例用不上。
3. **全局优化（模拟退火 / 局部搜索）**：只有在"候选位普遍不够"时才值得；当前 0/0/0 且最大位移
   已收到 65.5，没有可优化的目标函数了。
4. **"过路管线压到别人的字"那 4~5 处**：按第 2 节的惯例，**底框遮线是合规的**，
   而它压的是"文字带里的线"、不是"文字压文字/符号"。要彻底消掉得让设计器**搜索落点**
   （选边 + 选距离 + 迭代），成本远大于收益 —— 记在 `docs/upstream-gaps.md` 第 17 条备查。

## 7. 一句话给未来的自己

**先定"什么算错"，再谈算法**：文字压文字 / 文字压符号是错（硬指标，有棘轮）；
标签贴着自己的线、底框遮线是**惯例**；密集处放不下就用图例/指引线兜底，别拿图元间距去硬凑
（尺度无关，凑不动 —— 这条我们已经踩过两次）。
