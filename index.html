ICE Agent Console 是什么

ICE Agent Console 是一个把 AG-UI 协议接到 ICE 渲染家族（ice-render / ice-chart / ice-chart-dsl / ice-entity-designer / ice-web-components）上的开源在线演示，本质上是一张 数字孪生 / SCADA 风格的工业过程监控（智能水务）界面： agent 产生的事件流直接驱动浏览器里的 Canvas 画布 —— 画工艺图、画图表、画表单， 而不是把卡片插进消息流。

界面是反过来的：绘图区铺满整个视口、开页就画着图，对话面板浮在它的右边缘。 切界面等于在绘图区里换图层（工艺图 / 图表 / 表单，三种形态互斥）， 其中工艺图那一层是主视图，开页建好之后就不再重建。

开页画的是什么：某 10 万 m³/d 市政污水厂的 AAO 工艺流程

基准图是 78 个单元、100 段管线，用到 31 种符号种类与 9 种介质，按真实厂站的形态铺开： 两组并联生化线、配水井与集水井、多台鼓风机、多点加药、提标改造段、 污泥干化与两套除臭，每个工艺段都带在线仪表。

主流程

厂外进水 → 粗格栅 → 进水泵 → 细格栅 → 曝气沉砂池 → 初沉池 → 配水井 → 厌氧池 → 缺氧池 → 好氧池（AAO）→ 二沉池 → 中间提升泵 → 混凝沉淀池 → 滤布滤池 → 臭氧接触池 → 活性炭滤池 → 膜池（超滤）→ 消毒接触池 → 在线水质监测 → 出水计量 → 排放口。

配套系统

剩余污泥走污泥浓缩池 → 污泥脱水机 → 污泥干化机 → 污泥料仓 → 外运； 另有事故池与事故水回流泵、PAC / PAM / 次氯酸钠 / 碳源四个加药点（各配计量泵）、 鼓风机与变频器，以及出水 COD / 氨氮 / 总磷 / 总氮 / 浊度在线仪表。

三组"现实里必须有"的回路

二沉池出水高程不够，中间提升泵（两台互备）把水提进深度处理； 滤池反冲洗水回配水井；污泥浓缩上清液与脱水滤液也回配水井 —— 这三条回路补齐之后，图上的水量才平衡，才经得起一句"这不像真图"。

在这个页面上能做什么

  • 「看看污水处理工艺图」：镜头按工艺段推近，图元逐段高亮讲解，把主流程走一遍。
  • 「把工艺图放大」「让图元闪烁」：agent 用自定义事件在画布上推镜头、打高亮 —— 它们是瞬时的演示动作，不写进 state，刷新即消失。
  • 「提标改造」：用 JSON Patch（STATE_DELTA）动态增删图元 —— 拆一处、加三处，而画面不重画、视口不重置。
  • 「看看出水 COD 的趋势」「看看出水实时流量」：同一块绘图区切到图表图层， 那里是两块画布（图表 + 底部控件条），支持逐拍追加数据与联动。
  • 「调整加药量」：开一张加药与工艺参数调整单（药剂 / 投加点 / 投加量 / 执行周期）， 锚定到图上的 PAC 加药装置 DU-101。
  • 「给进水泵下发指令」：中断一轮 → 切到表单图层填泵站运行参数 → 带着 resume 开新的一轮。
  • 「故意画错工艺图」：把校验器的结构化诊断回灌给 agent，看它自修复 DSL。

技术要点

  • AG-UI 事件流：TEXT_MESSAGE、TOOL_CALL、STATE_SNAPSHOT、STATE_DELTA、CUSTOM、 RUN_FINISHED、RUN_ERROR；中断用 interrupt + resume 表达。
  • 纯核心 + 命令式外壳：归约器是纯函数、只吐 effects，碰 canvas 的活在绘图区那一层。
  • 两条 transport 共用同一份输入映射：连后端的 fetch + SSE， 或者把同一份剧本搬进浏览器（纯前端，产物可以直接静态托管）。
  • 图表实例只建一次（validateChartDsl → compileChartDsl → createChart / setOption）， 不在流式更新里反复重建。
  • TypeScript + webpack，MIT 许可。
